# PRD: Загрузка и хранение файлов встречи

**Дата**: 2026-07-31
**Статус**: Draft

## Цель

Позволить участникам встречи прикреплять к ней файлы (записи, транскрипты, документы) для последующего хранения и обработки, и видеть эти файлы прямо внутри карточки встречи.

## Пользовательские сценарии

- Участник встречи открывает страницу встречи -> видит блок с прикреплёнными файлами и элемент загрузки нового файла.
- Участник встречи загружает файл (запись, транскрипт или документ) -> файл появляется в списке файлов встречи со статусом загрузки/готовности.
- Участник встречи открывает страницу встречи, к которой уже прикреплены файлы -> видит список файлов с именем, типом, размером и датой загрузки.
- Участник встречи скачивает ранее загруженный файл -> получает исходный файл.
- Владелец встречи удаляет файл, прикреплённый к его встрече (свой или чужой) -> файл пропадает из списка и из хранилища.
- Участник, не являющийся владельцем встречи, пытается удалить файл -> получает отказ в доступе.
- Участник пытается загрузить, просмотреть или скачать файл во встрече, в которой он не участвует -> получает отказ в доступе.

## В скоупе

- Backend: эндпоинт загрузки файла в конкретную встречу (`POST /meetings/:id/files` или аналог), привязка файла к `Meeting` в БД (имя, mime-тип, размер, кто загрузил, дата).
- Backend: эндпоинт получения списка файлов встречи (`GET /meetings/:id/files`).
- Backend: эндпоинт скачивания файла (`GET /meetings/:id/files/:fileId`).
- Backend: эндпоинт удаления файла, доступный только владельцу встречи (независимо от того, кто файл загрузил).
- Backend: физическое хранение файлов на локальной файловой системе сервера API.
- Backend: место в модели данных под будущий статус обработки файла (например, `pending` / `processed`), без реализации самой обработки (транскрибации, суммаризации и т.п.) в этой итерации.
- Frontend: блок "Файлы встречи" на странице встречи со списком прикреплённых файлов (имя, тип, размер, дата, кто загрузил).
- Frontend: элемент загрузки файла (выбор файла, индикация процесса загрузки, ошибка загрузки).
- Frontend: возможность скачать файл из этого блока для всех участников; действие удаления файла видно и доступно только владельцу встречи.
- Ограничение доступа: загружать, просматривать и скачивать файлы могут все участники конкретной встречи (владелец + перечисленные participants); удалять файл может только владелец встречи.

## Не в скоупе

- Сама обработка файла: транскрибация аудио/видео, извлечение текста из документов, генерация саммари, экшн-айтемов и т.п. — только точка расширения в модели данных.
- Одновременная/потоковая загрузка нескольких файлов за один запрос.
- Просмотр содержимого файла внутри приложения (плеер, предпросмотр документа) — только скачивание.
- Версионирование файлов (замена/история версий одного файла).
- Уведомления участников о новом загруженном файле.
- Антивирусная проверка / модерация содержимого файла.

## Технические ограничения

- В текущей модели `Meeting` (`prisma/schema.prisma`) `participants` — это массив строк (предположительно email), не связь с реальными записями `User`; проверка "участник ли текущий пользователь" должна сопоставлять `request.user.email` со списком `participants` либо `ownerId`, а не полагаться на отдельную таблицу участников.
- Нужно задать конкретные лимиты на размер и допустимые типы файлов (аудио, видео, документы) и зафиксировать их в реализации — на момент написания PRD ограничение сформулировано как "любые типы встреч-файлов", жёсткий список mime-типов и максимальный размер должны быть определены до реализации.
- Загрузка больших медиафайлов (записи встреч) требует потоковой обработки на бэкенде, а не буферизации целиком в памяти.
- Файлы хранятся на локальной файловой системе сервера API (например, в выделенной директории на диске); путь/директория хранения и её исключение из системы контроля версий определяются на этапе реализации.
- Модуль файлов встреч должен быть отдельным CQRS-модулем по аналогии с `src/meetings/`, обращающимся к `MeetingsModule` через `CommandBus`/`QueryBus`, а не через прямой импорт, в соответствии с текущей архитектурой `apps/api`.

## Критерии готовности

- [ ] Участник встречи может загрузить файл через API и видит его в списке файлов встречи.
- [ ] Участник встречи может загрузить файл через UI встречи с индикацией процесса и ошибок загрузки.
- [ ] Список файлов встречи отображает имя, тип, размер и дату загрузки каждого файла.
- [ ] Участник встречи может скачать ранее загруженный файл и получить исходное содержимое.
- [ ] Владелец встречи может удалить любой файл этой встречи (свой или загруженный другим участником), и файл пропадает из списка и хранилища.
- [ ] Участник встречи, не являющийся её владельцем, не видит действие удаления и получает 403 при прямом вызове эндпоинта удаления.
- [ ] Пользователь, не являющийся участником встречи, получает 403/404 при попытке загрузить, просмотреть, скачать или удалить файл этой встречи.
- [ ] Загрузка файла, превышающего установленный лимит размера или недопустимого типа, отклоняется с понятной ошибкой на фронтенде.
- [ ] E2E-тест покрывает загрузку, получение списка, скачивание и удаление файла встречи.
